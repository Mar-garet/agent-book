# 阅读路线：从零走向设计判断

全书分为基础篇与专题篇。基础篇循序渐进地建立概念；专题篇围绕记忆、上下文、工具、协作和可靠执行组织材料。第一次接触 Agent，可以从开篇按顺序读；已有使用经验，可以直接进入关心的系统专题。

这份书稿的主线是一项贯穿案例：一家团队每天需要排查报表失败、准备修复方案，并向使用者提供可以核查的结果。任务会逐渐变长，会碰到错误、变更和权限限制。读者将看到，每加入一种困难，系统就需要承担一种新责任。

案例是为了讨论机制而设计的情境，不代表任何项目的实际运行结果。

## 专题一：记忆系统

从跨任务记忆开始，比较不同系统怎样保存与使用信息，再推导自己的记忆系统该怎样设计。

- [记忆系统：从项目比较到写入、检索与更新](15-memory-update-boundaries.md)——以 Hermes、OpenClaw 与 LangGraph 为例，讲清记录、存储、加载、更新和生效之间的关系。

## 专题二：上下文系统

沿输入的装配与压缩，理解模型能看见什么，以及系统怎样控制信息的取舍。

- [默认能力，是怎样被装配出来的？](13-context-and-defaults.md)——比较 Deep Agents 的默认机制与 Pi 的上下文投影。
- [摘要更短了，Agent 为什么反而忘了关键事实？](18-context-compaction.md)——追踪摘要前裁剪与信息损失，讨论继续执行需要保留哪些依据。

## 专题三：工具与 MCP 系统

从宿主如何接入工具，走到工具结果如何影响下一步，区分连接、执行与完成。

- [同一个 MCP 服务，为什么进入两个 Agent 后表现不同？](16-mcp-host-differences.md)——比较 Goose 与 Cline SDK 的发现、审批、缓存与结果处理。
- [工具返回了，任务为什么还没有完成？](17-tool-results-and-retries.md)——比较工具包装、错误转换与重试边界。

## 专题四：协作系统

把上下文、任务和责任交给另一个 Agent 时，谁继续拥有最终交付责任？

- [叫来更多 Agent，为什么还要有人收尾？](19-delegation-and-handoffs.md)——比较工具式委派与交接，追踪输入、结果与责任的流动。

## 专题五：可靠执行与评测

把权限、恢复、信任、预算和验收连起来，讨论一个系统怎样长期完成真实任务。

- [用户说了停，动作为什么还在发生？](12-action-boundaries.md)——比较 Pi 的调度与取消、Codex 的审批和执行边界。
- [从断点继续，为什么会再做一遍？](14-resume-and-side-effects.md)——用 LangGraph 的受控场景观察恢复与外部效果。
- [文档里的一句话，为什么变成了行动指令？](20-trust-boundaries.md)——追踪工具输出与记忆写入中的信任边界。
- [明明限制了步数，为什么还能花掉更多资源？](21-execution-budgets.md)——比较轮次、图步数、子运行与整项任务的预算。
- [谁来证明 Agent 真的完成了？](22-evaluation-and-completion.md)——从独立验收走到评测，区分一次成功、重复可靠性与真实交付。

专题篇可按问题跳读，也可沿以上顺序阅读。各专题先交代比较范围，再沿真实机制展开；记忆系统进一步串起完整的设计过程。文件路径保留原有编号，已有引用仍可使用。

## 当前覆盖范围

书稿建立概念和比较框架，再沿 Pi、Codex、Deep Agents、Hermes、OpenClaw、Goose、Cline SDK 与 OpenAI Agents SDK 的局部实现继续追踪。实验目录收录五组、共 31 个确定性场景，覆盖恢复、错误与重试、委派与轮数、摘要前裁剪，以及应用验收规则；没有调用外网模型或真实业务服务。

这些研究没有覆盖各项目的所有产品入口、配置或平台。其余案例保留在项目地图中，标明后续问题。运行成功率、延迟、成本与长任务稳定性仍需另建任务集测量，不能由局部源码或确定性场景推导。
