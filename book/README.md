# 阅读路线：从零走向设计判断

这本书从一个日常请求开始：请助手安排周末去杭州玩两天，总预算 1500 元。先给行程，不替你订票订房。

助手查了交通和住宿，为什么仍会漏掉返程？你说过喜欢安静，它为什么隔天又忘了？程序中断后继续，为什么日历里多出两条相同安排？我们沿着这些问题，理解工具、记忆、分工和恢复怎样配合，再比较开源项目采取的不同办法。

这是为讲解而设计的例子，不是实际出行记录。第一次读不需要认识任何项目，也不用安装框架。基础篇先讲清楚怎么工作，专题篇再讨论为什么这样做、还有什么选择。

## 选一条适合自己的路线

- **从零理解 Agent**：按下面四个基础阶段阅读，再进入系统专题。先看助手怎样一步步做事，再理解记忆、分工和结果检查。
- **准备设计一个系统**：先读[项目比较](10-project-comparisons.md)和[系统设计](11-design-and-experiments.md)两章，再沿记忆 → 上下文 → 工具 → 协作 → 可靠执行深入；每个专题都先讲具体困难，再比较实现与选择。
- **正在定位一次失败**：模型没看到关键要求，读[上下文与压缩](18-context-compaction.md)；规则更新后不生效，读[记忆](15-memory-update-boundaries.md)；重启后重复做同一件事，读[执行恢复](14-resume-and-side-effects.md)；几个助手一起花掉太多调用费用，读[预算](21-execution-budgets.md)；助手说做好了却还有遗漏，读[评测](22-evaluation-and-completion.md)。

基础篇无需先安装框架或准备模型密钥。正文用文字和图解释思路；想知道具体项目怎么实现，可以再看章末研究资料。复现实验另有环境要求；想先看一次无需模型服务的运行，可从[离线验收样例](../experiments/README.md#先运行一个无需模型的样例)开始。

## 专题一：记忆系统

从跨任务记忆开始，比较不同系统怎样保存与使用信息，再推导自己的记忆系统该怎样设计。

- [记忆系统：从项目比较到写入、检索与更新](15-memory-update-boundaries.md)——比较精选文件、后台整理和按需查找，解释写进记忆后为什么仍可能用不上。

## 专题二：上下文系统

看看用户要求、查询结果和旧消息怎样进入下一次请求；内容太多时，哪些可以省，哪些不能丢。

- [上下文系统：让下一步判断拿到合适的依据](13-context-and-defaults.md)——比较原样保留、筛选和保存原文后按需读取，讨论各自的代价。
- [上下文压缩：信息怎样在交接处丢失](18-context-compaction.md)——追踪摘要前裁剪与信息损失，讨论继续执行需要保留哪些依据。

## 专题三：工具与 MCP 系统

从宿主如何接入工具，走到工具结果如何影响下一步，区分连接、执行与完成。

- [工具与 MCP 系统：怎样让 Agent 可靠地接触外部世界？](16-mcp-host-differences.md)——比较工具怎么被找到、参数怎么检查、调用结果怎样交回来。
- [工具返回了，任务为什么还没有完成？](17-tool-results-and-retries.md)——分清查询失败、没有结果和任务没做完，决定哪些操作可以重试。

## 专题四：协作系统

交通和住宿分头查以后，谁把结果放在一起检查？怎样避免多请一个助手，反而多一堆麻烦？

- [协作系统：更多 Agent，怎样共同交付一份结果？](19-delegation-and-handoffs.md)——比较子任务、接手处理和团队调度，说明怎么分工、交回结果和统一检查。

## 专题五：可靠执行与评测

助手能做什么，中途停了怎么办，何时可以说做完了？把这些问题放在一起，讨论日常使用需要的可靠性。

- [可靠执行系统：让动作可控、过程可恢复、结果可核查](12-action-boundaries.md)——比较执行前的检查、过程记录和恢复，弄清怎样防止未获准或重复的操作。
- [从断点继续，为什么会再做一遍？](14-resume-and-side-effects.md)——用 LangGraph 的受控场景观察恢复与外部效果。
- [文档里的一句话，为什么变成了行动指令？](20-trust-boundaries.md)——追踪工具输出与记忆写入中的信任边界。
- [明明限制了步数，为什么还能花掉更多资源？](21-execution-budgets.md)——比较轮次、图步数、子运行与整项任务的预算。
- [评测系统：让任务完成成为可复核的结论](22-evaluation-and-completion.md)——提前说好完成条件，检查实际结果，并区分偶尔做对与稳定做对。

专题篇可按问题跳读，也可沿以上顺序阅读。各专题先交代比较范围，再沿真实机制展开，连接到应用设计与验证方法；恢复、压缩、错误与预算等问题另有深入篇。文件路径保留原有编号，已有引用仍可使用。

## 当前覆盖范围

书稿从基础概念走向五个系统专题。研究资料已按工具、上下文、记忆、规划与 Skills、协作、恢复、权限、预算、评测九个维度，核查全部 32 个项目的相关实现路径；[跨项目设计地图](../references/system-design-map.md) 汇总设计差异与取样边界。

实验目录收录五组、共 31 个确定性场景，涉及恢复、工具重试、委派预算、摘要输入和应用验收。它们没有调用外网模型或真实业务服务。正文中的旅行任务是教学情境，短代码用来说明机制。

相关实现的核查不等于覆盖每种配置与平台。运行成功率、延迟、成本与长任务稳定性仍需另建任务集测量。
