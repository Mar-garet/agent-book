# 阅读路线：从零走向设计判断

全书以设计思想为主线：先理解问题与约束，再比较机制，讨论选择的理由、代价和适用边界。开源项目提供案例，源码和实验为判断提供依据。

全书分为基础篇与专题篇。基础篇循序渐进地建立概念；专题篇围绕记忆、上下文、工具、协作和可靠执行组织材料。第一次接触 Agent，可以从开篇按顺序读；已有使用经验，可以直接进入关心的系统专题。

这份书稿的主线是一项贯穿案例：值班工程师请助手排查经营日报 R42 的失败，在生产只读的边界内准备修复方案，并在测试环境验证。任务会逐渐变长，会碰到错误、变更和权限限制。读者将看到，每加入一种困难，系统就需要承担一种新责任。

案例是为了讨论机制而设计的情境，不代表任何项目的实际运行结果。

## 选一条适合自己的路线

- **从零理解 Agent**：按下面四个基础阶段阅读，再进入系统专题。先建立行动循环，再理解记忆、分工和可靠性。
- **准备设计一个系统**：先读[项目比较](10-project-comparisons.md)和[系统设计](11-design-and-experiments.md)两章，再沿记忆 → 上下文 → 工具 → 协作 → 可靠执行深入；每个专题都把代表实现连到应用设计。
- **正在定位一次失败**：信息没进入输入，读[上下文与压缩](18-context-compaction.md)；规则更新后不生效，读[记忆](15-memory-update-boundaries.md)；恢复或重试重复写入，读[执行恢复](14-resume-and-side-effects.md)；父子运行成本失控，读[预算](21-execution-budgets.md)；结果看似完成却不合格，读[评测](22-evaluation-and-completion.md)。

基础篇无需先安装框架或准备模型密钥。正文先用自然语言和图示解释设计；希望继续核查实现的读者，可以按引用进入源码研究。复现实验另有环境要求；想先看一次无需模型服务的运行，可从[离线验收样例](../experiments/README.md#先运行一个无需模型的样例)开始。

## 专题一：记忆系统

从跨任务记忆开始，比较不同系统怎样保存与使用信息，再推导自己的记忆系统该怎样设计。

- [记忆系统：从项目比较到写入、检索与更新](15-memory-update-boundaries.md)——以 Hermes、OpenClaw 与 LangGraph 为例，讲清记录、存储、加载、更新和生效之间的关系。

## 专题二：上下文系统

沿输入的装配与压缩，理解模型能看见什么，以及系统怎样控制信息的取舍。

- [上下文系统：让下一步判断拿到合适的依据](13-context-and-defaults.md)——比较 Pi、Deep Agents 与 Codex 的输入装配、历史投影、结果外置与预算选择。
- [上下文压缩：信息怎样在交接处丢失](18-context-compaction.md)——追踪摘要前裁剪与信息损失，讨论继续执行需要保留哪些依据。

## 专题三：工具与 MCP 系统

从宿主如何接入工具，走到工具结果如何影响下一步，区分连接、执行与完成。

- [工具与 MCP 系统：怎样让 Agent 可靠地接触外部世界？](16-mcp-host-differences.md)——比较 Goose 与 Cline SDK，再设计发现、身份、授权、执行适配与结果消费的完整链路。
- [工具返回了，任务为什么还没有完成？](17-tool-results-and-retries.md)——比较工具包装、错误转换与重试边界。

## 专题四：协作系统

把上下文、任务和责任交给另一个 Agent 时，谁继续拥有最终交付责任？

- [协作系统：更多 Agent，怎样共同交付一份结果？](19-delegation-and-handoffs.md)——比较 SDK 委派、交接与 Deep Agents 子代理，再设计任务契约、调度、证据合并与总验收。

## 专题五：可靠执行与评测

把权限、恢复、信任、预算和验收连起来，讨论一个系统怎样长期完成真实任务。

- [可靠执行系统：让动作可控、过程可恢复、结果可核查](12-action-boundaries.md)——比较 Pi、Codex 与 LangGraph，将审批、动作状态、恢复和业务效果放在同一责任链中。
- [从断点继续，为什么会再做一遍？](14-resume-and-side-effects.md)——用 LangGraph 的受控场景观察恢复与外部效果。
- [文档里的一句话，为什么变成了行动指令？](20-trust-boundaries.md)——追踪工具输出与记忆写入中的信任边界。
- [明明限制了步数，为什么还能花掉更多资源？](21-execution-budgets.md)——比较轮次、图步数、子运行与整项任务的预算。
- [评测系统：让任务完成成为可复核的结论](22-evaluation-and-completion.md)——设计任务环境、执行适配、独立验收和重复评测，区分局部证据与真实交付。

专题篇可按问题跳读，也可沿以上顺序阅读。各专题先交代比较范围，再沿真实机制展开，连接到应用设计与验证方法；恢复、压缩、错误与预算等问题另有深入篇。文件路径保留原有编号，已有引用仍可使用。

## 当前覆盖范围

书稿从基础概念走向五个系统专题。研究资料已按工具、上下文、记忆、规划与 Skills、协作、恢复、权限、预算、评测九个维度，核查全部 32 个项目的相关实现路径；[跨项目设计地图](../references/system-design-map.md) 汇总设计差异与取样边界。

实验目录收录五组、共 31 个确定性场景，涉及恢复、工具重试、委派预算、摘要输入和应用验收。它们没有调用外网模型或真实业务服务。正文中的 R42 是贯穿全书的教学情境，短代码用来说明机制。

相关实现的核查不等于覆盖每种配置与平台。运行成功率、延迟、成本与长任务稳定性仍需另建任务集测量。
