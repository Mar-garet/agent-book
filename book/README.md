# 阅读路线：从零走向设计判断

第一次接触 Agent，可以按顺序读。已有使用经验，可以先读开篇，再到第十章检查自己如何比较项目；遇到不熟悉的概念，再回到对应章节。

这份书稿的主线是一项贯穿案例：一家团队每天需要排查报表失败、准备修复方案，并向使用者提供可以核查的结果。任务会逐渐变长，会碰到错误、变更和权限限制。读者将看到，每加入一种困难，系统就需要承担一种新责任。

案例是为了讨论机制而设计的情境，不代表任何项目的实际运行结果。

## 第一阶段：看见一个 Agent 如何工作

0. [你真的懂 Agent 吗？](00-do-you-really-understand-agents.md)——从一次看似成功的任务，追问是谁完成了工作。
1. [模型之外，谁让事情继续发生？](01-model-agent-and-harness.md)——建立模型、工具、运行系统与环境的基本关系。
2. [从一次回答，到一个行动循环](02-the-agent-loop.md)——观察、行动、反馈、状态与停止。

## 第二阶段：理解 Agent 怎样接触世界

3. [工具调用：一次请求，几层责任](03-tool-calling.md)——描述、参数、权限、执行、反馈和副作用。
4. [MCP：把连接标准化之后，问题还剩什么？](04-mcp.md)——宿主、客户端、服务端之间的协作。
5. [上下文：Agent 此刻究竟看见了什么？](05-context.md)——选择、压缩、检索与信息损失。
6. [记忆：存下来之后，怎样影响下一次行动？](06-memory.md)——会话状态、检查点、长期知识与经验。

## 第三阶段：理解长期工作中的取舍

7. [规划与方法：下一步由谁决定？](07-planning-and-methods.md)——ReAct、先规划后执行、状态图与混合控制。
8. [Skills 与多 Agent：经验和分工怎样进入系统？](08-skills-and-multi-agent.md)——可复用做法、任务委派、上下文隔离与协调成本。
9. [可靠性：什么时候可以相信它完成了？](09-reliability.md)——验收、权限、恢复、幂等与评测。

## 第四阶段：形成自己的判断

10. [把项目放在同一张问题地图上](10-project-comparisons.md)——比较 Pi、Codex、LangChain、LangGraph、Deep Agents 等不同选择。
11. [从一个演示，到一个能长期工作的系统](11-design-and-experiments.md)——把前面的问题串成设计与实验。

## 第五阶段：沿真实机制深入

12. [用户说了停，动作为什么还在发生？](12-action-boundaries.md)——Pi 的批次调度、取消与新指令，Codex 的审批和执行边界。
13. [默认能力，是怎样被装配出来的？](13-context-and-defaults.md)——Deep Agents 的默认配置、Pi 的上下文投影，以及子任务共享了什么。
14. [从断点继续，为什么会再做一遍？](14-resume-and-side-effects.md)——用四个真实运行的 LangGraph 受控场景观察恢复与外部效果。
15. [已经记住了，为什么还要等到后来才生效？](15-memory-update-boundaries.md)——Hermes 与 OpenClaw 的写入、缓存、检索、加载和整理。
16. [同一个 MCP 服务，为什么进入两个 Agent 后表现不同？](16-mcp-host-differences.md)——Goose 与 Cline SDK 怎样组织工具身份、发现、审批、缓存和错误。

这一阶段延续前面的任务情境，沿固定版本的实现解释边界。源码静态观察与实际运行的实验分别标明；读者无需先读完研究笔记。

## 第六阶段：从局部动作走向完整交付

17. [工具返回了，任务为什么还没有完成？](17-tool-results-and-retries.md)——分清回执、错误与完成，观察重试为何重复已经成功的动作。
18. [摘要更短了，Agent 为什么反而忘了关键事实？](18-context-compaction.md)——沿 Pi 的真实输入裁剪，追踪信息在摘要之前怎样丢失。
19. [叫来更多 Agent，为什么还要有人收尾？](19-delegation-and-handoffs.md)——区分工具式委派与交接，解释输入、结果和责任怎样转移。
20. [文档里的一句话，为什么变成了行动指令？](20-trust-boundaries.md)——追踪工具输出、目录更新和记忆写入中的信任边界。
21. [明明限制了步数，为什么还能花掉更多资源？](21-execution-budgets.md)——分清轮次、图步数、子运行与整项任务的预算。
22. [谁来证明 Agent 真的完成了？](22-evaluation-and-completion.md)——从独立验收走到评测，区分一次成功、重复可靠性与真实交付。

这一阶段把工具、上下文和分工重新连到任务结果。部分机制配有确定性实验；业务验收使用人工构造的反例，不将这些检查当作模型成绩。

## 当前覆盖范围

书稿建立概念和比较框架，再沿 Pi、Codex、Deep Agents、Hermes、OpenClaw、Goose、Cline SDK 与 OpenAI Agents SDK 的局部实现继续追踪。实验目录收录五组、共 31 个确定性场景，覆盖恢复、错误与重试、委派与轮数、摘要前裁剪，以及应用验收规则；没有调用外网模型或真实业务服务。

这些研究没有覆盖各项目的所有产品入口、配置或平台。其余案例保留在项目地图中，标明后续问题。运行成功率、延迟、成本与长任务稳定性仍需另建任务集测量，不能由局部源码或确定性场景推导。
