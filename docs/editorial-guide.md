# 写作与研究约定

本书要帮助读者形成判断：当任务、环境和限制发生变化时，能够解释一种 Agent 设计为什么成立，以及它会在哪里失效。

## 每章从一个具体困难开始

先把读者放进情境，再给机制命名。例如，先让一个任务中断，再解释检查点；先让一次写入返回超时，再解释幂等；先让模型记错项目规则，再解释记忆的更新与失效。

术语第一次出现时用中文解释。读者应当先理解谁在做事、信息怎样流动，再接触工具名、协议名和实现文件。

正文采用自然的阅读语言，引用称为来源或参考资料，运行观察称为实验记录。章节用论述收束，不安排自测、作业或练习。

## 让贯穿案例真的向前走

R42 是教学情境：生产运行 run-807，业务日期 10 月 16 日，核对窗口 15–16 日；生产只读，测试验证。job-42 执行完成但缺少 16 日数据，完成草稿被验收拦下。后文补齐诊断、方案和授权，最终用新的 job-43 展示验收闭环。未来时区规则从 19 日生效，不能反过来改变历史报表口径。

每章增加一个具体困难，保留上一章已经查明的事实；回看旧步骤时明确说明，避免同一任务反复重新开始。设计情境中的事件不能写成实际实验结果，结尾推演也不增加实验样本数。

比较应帮助读者作决定：在什么任务和约束下选哪一种结构，要承担什么代价。研究进度、待采样项目与详细调用清单放到附录或研究记录；正文保留影响判断的版本、配置和证据边界，不反复用同一组资格声明打断阅读。

## 基础篇与系统专题怎样衔接

基础篇按概念递进，帮助读者理解参与者与完整执行过程。专题篇按记忆、上下文、工具、协作和可靠执行组织材料；章节路径保留原编号作为稳定标识，不用它表示新的阅读顺序。

每个系统专题先交代真实困难，再在相同维度下比较代表项目，沿调用链解释实现，最后提炼可用于自己系统的设计方法与验证依据。比较之前说明层次、固定版本和配置范围。记忆、上下文、工具、协作、可靠执行与评测分别沿这条结构展开；局部机制另有深入篇，与主章相互衔接。

视觉内容承担解释任务：比较矩阵用于同维度对照，流程图与时序图说明责任和数据流动，重点说明使用标准 GFM 提示块。Mermaid 首行可用 `%% 图题` 提供中文图题。正文、原始 Markdown 和网站保持同一份内容，不依赖网页专属 HTML 隐藏关键信息。

## 用同一组问题比较项目

每轮研究先确定场景、任务、版本和配置，再追问：谁决定下一步，谁执行动作，状态保存在哪里，工具怎样暴露，权限在哪里检查，错误怎样返回，怎样恢复，如何判断完成。

不能因为一个运行系统内置了某项功能，就推断使用框架的人无法实现同样的功能。也不能因为框架可以扩展，就宣称它开箱即用地解决了全部问题。

## 给不同强度的结论不同写法

**材料支持的事实**需要指向固定版本中的文档或源码。README 能证明项目如何描述自己；实际调用顺序、默认配置和异常行为，通常还需要继续看实现。

**设计推断**需要写清前提。例如，“默认工具更少可能降低选择负担”是推断；它是否改善某项任务的成功率，需要实验。

**实验结论**必须保留输入、环境、配置、运行次数、原始轨迹和判断口径。模型效果评测还需记录模型与任务集；不调用模型的机制实验应明确模拟了什么、没有覆盖什么。没有运行记录时，只能提出实验方案。

对某项能力尚未找到相关实现时，写“本轮未核对”，不要写“不支持”。

## 让源码成为论据

正文先给读者一个可以理解的过程，分析过程与引用来源接放在论断附近或章末。避免连续罗列类名、内部路径和配置项。需要展示框架入口时，明确哪些是真正由调用者触发的入口，哪些是请求数据、业务适配器和支持基础设施。

引用上游材料时优先使用自己的解释，保留原作者的出处，少量摘录才使用引号。源码快照由 Git 子模块和 SOURCES.json 共同记录；在线文档需记录查询日期，避免把后来更新的网页当成旧版本行为的证明。

## 后续深化顺序

先逐项验证代表案例的关键执行链，再扩展到其余项目。优先补工具错误传播、上下文压缩的信息损失、记忆冲突处理、恢复后的副作用重复，以及多 Agent 的结果汇总。

每完成一个项目的研究，应让某个主题章节更具体。研究记录可以逐项目保存，正文仍围绕问题组织。

## 维护引用与实验记录

源码笔记保存在 [研究目录](../references/studies/README.md)，可运行实验与结果保存在 [实验目录](../experiments/README.md)。阅读了上游测试，不等于本轮运行了测试；源码推断、模拟服务和真实服务观察需分别说明。

修改正文后，在本书根目录运行：

```bash
python3 scripts/check_book.py
git diff --check
```

校验脚本检查本地链接与标题、固定提交与引用行号、32 个子模块指针，以及实验记录中的代码摘要。在未初始化子模块的独立书稿工作树中，可用 `--source-root /path/to/agent_book` 指向已有源码。

脚本不验证论断的语义正确性。修改实验代码后，需要重跑实验再保存新结果；仅修改正文且没有改变实验前提时，不必制造重复运行记录。
