# 术语表

忘了一个词，可以在这里找回它在本书里的意思。先看旅行例子，再看说明。不同项目可能用同一个词指不同范围，阅读源码时还要核对。

| 术语 | 用旅行助手来理解 |
| --- | --- |
| 模型 | 根据收到的材料，想下一步查什么、怎样回答。它说“我要查车次”，不代表查询已经发生。 |
| Agent | 围绕一个目标，一边取得新信息、一边决定下一步的系统。模型之外，还包括实际执行和记录工作的程序。 |
| 运行系统 / harness | 接住模型请求的程序：准备材料、调用工具、记下结果、安排下一轮。各项目所指的范围可能不同。 |
| 中间处理逻辑 / middleware | 放在某一步前后的处理程序，例如发给模型前删掉广告，调用工具前检查是否允许下单。需要实际启用才会生效。 |
| 模型配置 / profile | 与某种模型配套的设置，例如能接收多少输入。不同项目也可能用这个词指别的配置。 |
| 工具 | 真正查询车次、读取网页或添加日历的能力。模型看见工具说明，才知道可以请求它。 |
| 工具调用 | 模型提出查询和参数，程序检查后交给工具，工具再返回结果。 |
| 工具错误消息 | 把“酒店查询失败”作为一条结果告诉模型，让它决定换查询还是停下。与让异常直接中断程序不同。 |
| 回执 | 服务说“收到请求了”，可能附一个编号。它不一定表示行程文件已经生成。 |
| MCP | 应用与工具服务之间的一套共同说法，约定怎样列出能力、发送调用等。用户预算和下单许可仍要由应用管理。 |
| 宿主 | 运行助手的那个应用。它管理模型、工具连接和自己的规则；MCP 客户端是它用于与服务通信的部分。 |
| 信任边界 | 用户说“不下单”，网页说“立即付款”，这两句话的权力不同。程序要分清谁有权提出要求。 |
| 提示注入 | 网页等外部材料夹带命令，诱使助手把查到的文字当成用户指令，例如要求它忽略预算。 |
| 上下文 | 这一次实际发给模型的材料。电脑里有完整网页，不代表模型这次看到了它。 |
| 上下文投影 | 从保存的对话和记录里，按规则整理出这一次要给模型看的消息。原始记录与当前输入因此可能不同。 |
| 缓存失效 | 让程序不再沿用旧副本，有机会读到更新后的内容。文件更新、重新读取和模型收到更新，并不是同一步。 |
| 压缩 / compaction | 把一部分长对话整理成较短内容，给后续工作腾空间。要留意关键要求有没有被省掉。 |
| 裁剪 / truncation | 按长度直接截掉内容。例如只取酒店网页前一段，后面的“周六无房”可能就没了。 |
| RAG | 先从资料里查找相关内容，再把选中的部分交给模型。找到了相似文字，还要检查是不是这次旅行适用的信息。 |
| 任务状态 | 简明记录现在做到了哪里：去程已查、返程未查、草稿没通过检查。与保存全部聊天的用途不同。 |
| 检查点 | 保存一份进度，方便程序停止后继续。它不会自动删除日历里已经创建的安排。 |
| 长期记忆 | 保存以后还会用到的信息，例如用户喜欢安静住处。还要安排下一次怎么找回和使用。 |
| Skill | 可以按需读取的一份做事说明，也可带辅助资源。例如介绍整理行程的方法；不能代替强制执行的权限检查。 |
| ReAct | 让模型的判断与实际行动交替进行：先查车次，看过结果，再决定换班次还是继续。 |
| 规划 | 安排接下来做什么、什么先做、怎样算完成。查到酒店没房时，计划也应改变。 |
| 委派 | 主助手把“查住宿”交给另一个助手，等它带回结果。最后仍由主助手汇总检查。 |
| 交接 / handoff | 把后续对话或处理工作转给另一个助手接手。需要说清它拿到哪些资料、允许做什么。 |
| 沙箱 | 限制代码能碰到哪些文件、网络或账号的执行环境。与“这次用户有没有批准”是不同检查。 |
| 幂等 | 同一添加日历请求发了两次，服务能识别出来，仍只生成一条日程。需要调用方和服务共同约定。 |
| 动作标识 | 给某一次操作留的稳定标记，用来确认重试的是同一次添加，而不是用户新安排的另一趟旅行。 |
| 节点重入 | 程序恢复时，从某个步骤的开头重新运行。刚才执行过的代码可能再做一次。 |
| 重试范围 | 出错后究竟重做多少：只查一次酒店，还是连已经成功的车次查询也一起重做。 |
| 副作用 | 操作确实改变了外部东西，例如新增日历或创建订单。重复查询和重复下单的后果因此不同。 |
| 执行预算 | 限制助手运行消耗多少调用次数、时间或费用。与用户旅行的1500元预算是两件事。 |
| 任务验收 | 按提前说好的要求检查结果，例如两天齐全、没超预算、没有擅自下单。助手说“好了”还不够。 |
| 确定性机制实验 | 用固定输入和预先安排的响应，检查程序某一小步会怎样运行。它不测模型完成真实任务的概率。 |
| 轨迹 / trace | 一次任务的过程记录：发给模型什么、调用什么工具、得到什么结果、后来怎样继续。 |
| 评测 / eval | 在规定任务与条件下，检查系统做得如何。一次真实运行、小型程序检查和设想中的实验要分开说明。 |
