# 术语表

这些定义用于保持本书的讨论一致。不同项目可能使用不同边界，阅读项目材料时需要核对其具体含义。

| 术语 | 本书中的含义 | 容易混淆的地方 |
| --- | --- | --- |
| 模型 | 根据本轮输入生成内容或动作请求的推理服务 | 模型之外还有实际组织和执行工作的系统 |
| Agent | 围绕目标，根据观察选择行动，并利用反馈继续推进的系统 | 这是本书的工作定义，不代表唯一行业定义 |
| 运行系统 / harness | 围绕模型组织输入、执行、状态、工具与边界的支撑 | 各项目对它所覆盖的范围有不同约定 |
| 工具 | 提供一种可执行能力的接口与实现 | 描述工具和实际执行工具是不同环节 |
| 工具调用 | 模型或程序请求某项能力，由执行器分派并返回结果的过程 | 返回文本需要进一步解释其业务状态 |
| MCP | 系统之间暴露与调用工具等能力的协议 | 宿主仍需组织目标、策略与后续执行 |
| 宿主 | 运行 Agent 并管理模型交互、工具连接与本地策略的应用 | MCP 客户端在宿主一侧负责协议交换 |
| 上下文 | 本轮模型请求实际获得的信息 | 磁盘里保存的全部信息不会自动进入输入 |
| 压缩 / compaction | 用较短表示替代部分历史输入 | 需要检查丢失的细节与原文回查路径 |
| RAG | 先检索资料，再将选定内容提供给模型的做法 | 检索相关性需要结合时效、来源与适用范围 |
| 任务状态 | 对当前进度、事实、假设和待办的表示 | 聊天记录还保留了可能已被推翻的过程 |
| 检查点 | 可保存并用于恢复的某个时刻的执行状态 | 恢复执行状态不自动回退外部世界 |
| 长期记忆 | 跨会话保留并能在以后被采用的信息与机制 | 存储、找回、使用和失效需要分别设计 |
| Skill | 可按需加载的工作说明及辅助资源 | 必须强制的边界还需要执行机制落实 |
| ReAct | 将推理与环境行动交替组织的方法 | 重点是决策受到新观察影响 |
| 规划 | 对后续步骤、依赖与完成条件的安排 | 计划需要随着新信息修订 |
| 委派 | 将子任务交给另一执行者，并接收其结果 | 主任务仍需汇总和验收 |
| 交接 / handoff | 将后续处理职责转移给另一个执行者 | 要明确传递哪些状态与授权条件 |
| 沙箱 | 对进程可接触的资源与操作施加隔离限制的环境 | 隔离机制与动作审批承担不同责任 |
| 幂等 | 重复请求同一业务动作时，不重复产生本不该重复的效果 | 需要业务语义与工具实现共同支持 |
| 副作用 | 动作对外部世界产生的改变 | 重试和恢复时需要核对是否已发生 |
| 轨迹 / trace | 一次任务中输入、动作、观察和状态变化的记录 | 最终回答无法独自还原完整过程 |
| 评测 / eval | 在明确任务、配置与口径下检查行为和结果 | 未运行的实验方案不能当作测量结论 |
