# 源码研究：让一条设计判断可以被复核

正文负责解释问题，研究记录负责保留完整证据链。这里的五份记录都采用 [SOURCES.json](../../SOURCES.json) 固定的本地快照，核对日期为 2026-10-17；引用同时指向本地文件和 GitHub 固定提交。

阅读上游实现和测试，可以确认程序写下了怎样的约定。实际运行则能观察某组环境与配置中的行为。两种证据分别标明，不互相替代。

## 从正在追问的问题进入

- **为什么新指令没有立即改变动作？**[Pi 与 Deep Agents](pi-deepagents-execution.md) 追踪一批工具的准备、执行和反馈，再比较默认装配、上下文投影和子任务状态。对应 [第十二章](../../book/12-action-boundaries.md) 与 [第十三章](../../book/13-context-and-defaults.md)。
- **模型请求一个动作后，谁允许它发生？**[Codex 工具执行](codex-tool-execution.md) 沿命令与 MCP 两类路径分清策略、审批、隔离、重试与结果。对应 [第十二章](../../book/12-action-boundaries.md)。
- **恢复为什么会重复外部动作？**[LangGraph 中断与恢复](langgraph-interrupt-resume.md) 将节点重入、检查点与业务效果联系起来。对应 [第十四章](../../book/14-resume-and-side-effects.md)，另有 [实验复现](../../experiments/README.md)。
- **记忆写入成功后，何时影响下一轮？**[Hermes 与 OpenClaw](openclaw-hermes-memory.md) 区分持久文件、运行缓存、索引、实际请求与后台整理。对应 [第十五章](../../book/15-memory-update-boundaries.md)。
- **同一个 MCP 服务为何呈现不同工作方式？**[Goose 与 Cline SDK](goose-cline-mcp.md) 比较工具发现、身份、目录更新、审批与输出处理。对应 [第十六章](../../book/16-mcp-host-differences.md)。

## 哪些已经运行

LangGraph 实验运行了四个受控场景：同节点中断、拆分节点、业务去重，以及外部写入后注入异常。记录包含源版本、环境、代码摘要、状态与服务事件；实验不调用模型，使用同进程内存检查点和模拟服务。

其余四份研究是静态源码核对。记录中提到的上游测试并未在本轮执行，建议实验也尚未执行。它们不能证明任务成功率、性能、整体安全性或某个项目全面优于另一个。

## 怎样继续积累证据

每次先限定产品入口、配置和任务，再沿调用链找实际输入、动作、状态交付与错误。遇到结论不完整时，保留问题；遇到旧概括与源码冲突时，修改正文并在记录中说明准确边界。

维护者可运行 [书稿校验脚本](../../scripts/check_book.py) 检查链接、引用行号、固定版本与实验代码摘要。脚本检查资料之间是否一致，论断本身仍需阅读证据判断。
